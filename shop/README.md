# DaMark — сайт, админка и дашборд (шаблон)

Шаблон, чтобы показать владелице, как это будет выглядеть и работать. Товаров
в нём нет. Всё, что добавите, хранится только в браузере, на котором вы это
делаете: это демо, а не рабочий магазин.

## Что внутри

**Сайт для покупателей** (`#/`)

- Каталог: поиск, фильтр по категории и размеру. Пометка «Заброньовано», если
  вещь взяли на эфире. Проданное исчезает с сайта само.
- Страница товара: фото, размер, замеры, состояние, описание, код `DM-0001`.
  Внизу предупреждение о мошенниках: оплата только на ФОП.
- «Оформити замовлення»: покупатель вводит ФИО, телефон, город и отделение
  Новой почты. Вещь сразу бронируется, в админке появляется заказ с пометкой
  «З сайту». Затем покупателя просят самого написать менеджеру номер
  заказа: магазин по-прежнему не пишет первым.

**Админка** (`#/admin`, на телефоне — нижнее меню)

| Раздел | Что делает |
| --- | --- |
| Огляд (дашборд) | Выручка и прибыль за 7 или 30 дней, сравнение с прошлым периодом, график по дням, заказы по этапам, «Потребує уваги» (бронь не оплачена дольше суток, оплачено — надо отправить, отказ от посылки), ближайший эфир |
| Товари | Добавить вещь с телефона: фото (сжимаются сами), размеры в один тап, замеры, описание, цена продажи и закупки, партия, статус |
| Ефіри | Подготовить эфир: выбрать вещи, у каждой появляется номер лота. Во время эфира: ввести номер из комментария («7») → Enter → вписать ник → Enter, и бронь с заказом созданы. «Список для Telegram» копирует лоты с ценами, чтобы вставить в группу наличия |
| Замовлення | Нове → Очікує оплату → Оплачено → Відправлено → Отримано, одной кнопкой. «Реквізити» копирует готовое сообщение с суммой и ФОП. У оплаченного заказа кнопка «Створити ТТН», если оплаченных несколько — «ТТН для всіх оплачених». Номер ТТН ведёт на отслеживание Новой почты, «ТТН клієнту» копирует сообщение об отправке. Статус товара меняется сам |
| Клієнти | Собираются из заказов: сколько купила, сколько отказов. Чёрный список; при брони такого клиента админка предупредит |
| Закупівлі | Мешок или партия и сколько она стоила → сколько вещей продано и окупилась ли |
| Налаштування | Контакты, ФОП, IBAN, сколько держать бронь. Отправитель для Новой почты. Установка админки на телефон. Ссылки с примером. План подключений (бот, банк). Кнопки «Заповнити прикладом» и «Очистити все» |

«Заповнити прикладом» загружает выдуманные товары и заказы, чтобы показать
дашборд с цифрами. По умолчанию шаблон пустой. Ссылка с `?demo=1` в конце
(`…/shop/#/admin?demo=1`, `…/shop/#/?demo=1`) открывается уже с примером,
но то, что человек добавил сам, не трогает.

### ТТН Новой почты

В демо кнопка показывает весь путь: проверяет, хватает ли данных, создаёт
накладную, переводит заказ в «Відправлено» и готовит сообщение клиенту. Номер
при этом выдуманный и помечен «демо», в Новую почту ничего не уходит.

Для настоящих ТТН нужен ключ API из бизнес-кабинета Новой почты и сервер:
ключ нельзя держать в публичной странице. Сервер вызывает
`InternetDocument.save` от имени отправителя из «Налаштувань». Место, куда
это встаёт, — функция `createWaybill` в `src/lib/novaPoshta.ts`, экраны
менять не придётся.

## Как показать

Готовая сборка — папка `dist/` после `npm run build`. Это статические файлы,
сервер не нужен:

- **Netlify Drop:** https://app.netlify.com/drop → перетащить папку `dist`
  → получите ссылку, её можно открыть на телефоне.
- **Локально:**

```bash
npm install
npm run dev        # http://localhost:5173/
npm run build      # dist/
npm run typecheck
```

Адреса построены через `#` (`/#/admin`), поэтому работают на любом хостинге без
настроек.

Админка собирается отдельным файлом. Покупатель, который открыл каталог из
TikTok, её не скачивает. Если сайт обновили, пока страница была открыта,
страница один раз перезагружается сама и подхватывает новую версию.

## Устройство

```
src/
├── lib/
│   ├── types.ts      модель данных: товар, заказ, эфир, закупка, настройки
│   ├── store.ts      хранилище (сейчас localStorage) и правила статусов
│   ├── stats.ts      цифры для дашборда: выручка, прибыль, что требует внимания
│   ├── messages.ts   готовые тексты: реквизиты, ТТН, список лотов
│   ├── novaPoshta.ts ТТН: черновик из заказа, проверка, создание (демо)
│   ├── images.ts     сжатие фото перед сохранением
│   └── demo.ts       выдуманный пример (только по кнопке)
├── shop/             сайт для покупателей
├── admin/            админка и дашборд
└── components/       иконки, бейджи, график, модальные окна
supabase/schema.sql   та же модель как таблицы Postgres + права доступа
```

Экраны работают только через функции из `src/lib/store.ts`. Чтобы сделать
рабочую версию, этот файл переписывается на запросы к базе, а экраны остаются
как есть.

`supabase/schema.sql` проверена на чистом Postgres 16 с ролями Supabase.
Сайт без входа видит только вещи в продаже, их размеры и фото, а также
контакты. Закупочные цены, заказы, клиентов и IBAN он не видит. Владелица после
входа видит всё.

## Чего в шаблоне нет (это следующие этапы)

- Настоящего входа в админку и общей базы. Сейчас у каждого браузера свои
  данные, и любой, кто откроет `#/admin`, попадёт в админку.
- Хранения фото на сервере. Сейчас фото лежат в памяти браузера (IndexedDB),
  для показа этого хватает с запасом.
- Настоящих ТТН (см. выше), Telegram-бота, банка, чтения комментариев из
  TikTok. Они описаны в «Налаштуваннях» как план.
